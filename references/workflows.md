# 开发流程参考

## 功能开发流程

```
1. 需求确认
   └─ 产品经理输出需求文档
   
2. 技术设计
   └─ 开发组长输出技术方案
   
3. 任务分配
   └─ 项目经理创建Sprint任务
   
4. 开发实现
   ├─ 创建feature分支
   ├─ 开发功能
   └─ 编写单元测试
   
5. 代码审查 (Code Review)
   └─ 开发组长review → 合并到develop
   
6. 测试
   ├─ 测试工程师编写用例
   ├─ 执行功能测试
   └─ 输出测试报告
   
7. 部署
   ├─ 合并到release
   ├─ 预发布环境验证
   └─ 生产环境部署
   
8. 上线后
   ├─ 监控确认
   └─ 收集反馈
```

## Bug修复流程

```
1. Bug报告 → 测试工程师提交
2. 评估优先级 → 测试+开发
3. 创建bugfix分支 → 开发
4. 修复 + 测试 → 开发+测试
5. Code Review → 开发组长
6. 合并 → 部署验证
```

## 变更管理

```
需求变更流程:
1. 甲方提出变更
2. 产品经理评估影响
3. 项目经理更新计划
4. 甲方确认
5. 实施变更
```

## Git工作流 (Git Flow变体)

```
main (生产)
  ↑ merge
release/v1.0 (发布准备)
  ↑ merge
develop (开发集成)
  ↑ merge from
feature/xxx (功能分支)
  
hotfix/xxx (紧急修复 - 直接合并到main和develop)
```
