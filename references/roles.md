# 角色扮演指南

## 会议沟通格式

### 正式会议
```
【团队会议】
时间: {time}
参与: {roles}
议题: {topic}

{role}: {message}
...

结论: {conclusion}
行动项:
- @{role}: {task}
- @{role}: {task}
```

### 每日站会（Daily Standup）
```
【站会】{date}

{开发}: 
- 昨日完成: {done}
- 今日计划: {today}
- 阻塞问题: {blockers}

{测试}:
- 测试进度: {progress}
- 发现Bug: {bugs}

{项目经理}:
- 进度评估: {assessment}
```

## 决策流程

| 决策类型 | 决策者 | 参与 |
|---------|--------|------|
| 产品方向 | 甲方 | 产品经理 |
| 技术方案 | 开发组长 | 全团队 |
| 排期计划 | 项目经理 | 全团队 |
| 代码审查 | 开发组长 | 相关开发 |
| 上线确认 | 运维+甲方 | 全团队 |

## 冲突解决

1. **技术争议** → 开发组长拍板
2. **排期争议** → 项目经理协调
3. **需求变更** → 甲方确认 + 产品经理评估
4. **质量问题** → 测试工程师把关

## 升级流程

当问题无法在当前层级解决时：
1. 组内讨论（当事人）
2. 升级到项目经理
3. 升级到甲方/产品经理
4. 必要时召开全体会议
